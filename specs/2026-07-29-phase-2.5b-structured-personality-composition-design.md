# Phase 2.5b — Structured Personality Composition

> **Status:** Design approved
> **Branch:** `feat/wacky-manor-poc` (casehubio/examples)
> **Depends on:** eidos#107 (landed on upstream/main), Phase 2.5 (validated)

## Goal

Validate that structured personality frameworks (Jungian cognitive functions, Belbin team roles) produce measurably different autonomous character behavior compared to flat string dispositions. Run an incremental composition experiment — each layer adds one framework and measures its contribution — to produce evidence that composition actually does something.

## Eidos Change (on main)

Extend `ClasspathYamlDescriptorRegistrar.DispositionConfig` to support two new optional YAML fields:

- `mbtiType` (String) — convenience shorthand (e.g. `ENTJ`). Resolved via `MbtiTypeTerm.valueOf()` → `defaultProfile()` to produce the 8-function weighted `dispositionProfile`.
- `dispositionProfile` (list of `{term, weight}`) — direct weighted profile for cases that don't map to a standard MBTI type.

If `mbtiType` is set, it generates the `dispositionProfile` automatically. If both are set, explicit profile wins. The `toDescriptor()` method wires these into `AgentDisposition.builder().dispositionProfile(...)`.

The `dispositionVocabulary` field already parses from YAML. No breaking changes.

## Test Methodology

Four layers, run sequentially. Same autonomous scenario each time (tea-poisoning, max 180 turns, verdict: POISONED or TURN_LIMIT).

### Layers

**Layer 0 — Baseline (current):** Flat string dispositions, no vocabulary grounding. Run scenario, capture transcript. This is the control.

**Layer 1 — Jungian only:** Replace flat dispositions with `mbtiType` profiles. `dispositionVocabulary: urn:casehub:vocab:jungian`. Axes auto-derived. Run scenario, capture transcript.

**Layer 2 — Jungian + Belbin (composite):** Add `slotVocabulary: urn:casehub:vocab:belbin` and Belbin role assignments alongside Jungian profiles. Run scenario, capture transcript. This is the target state — the full composite profile.

### Profile Switching

A `manor.scenario.profile` config property selects which descriptor variant to load: `baseline`, `jungian`, `belbin`, `composite`. This avoids editing YAML between runs. The `ScenarioMode` property (`scripted`/`autonomous`) remains orthogonal.

### Evaluation

**Qualitative:** Read transcripts per layer. Are characters more differentiated? Does cognitive style visibly influence decision-making? Does Belbin role change group interactions?

**Quantitative:** Score transcripts with eidos-eval judges:
- `MbtiAlignmentJudge` — does behavior match declared type?
- `FunctionActivationJudge` — are the right cognitive functions activated?

Compare scores across layers.

### Verdict Gates

- Layer 1 vs 0: Did Jungian profiles change behavior measurably? If no → profiles aren't reaching the LLM effectively.
- Layer 2 vs 1: Did Belbin add observable signal beyond Jungian? Is the composite coherent — do the frameworks reinforce or contradict?

## DISC Exclusion

DISC is excluded from the experiment. The `personality-frameworks.md` compatibility table marks `Jungian + DISC = Redundant` — both project onto the same Conscientiousness axes via `axisExactMatch`. Thomas-Kilmann is implicit in every Jungian step (functions auto-derive `conflictMode` via cross-vocabulary projection).
